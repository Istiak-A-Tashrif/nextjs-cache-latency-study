# Frozen descriptive measurement protocol (20 October 2026)

This study uses no predictive model, staleness measurements, other framework, real-network relay, HTTP/2 or concurrent load.

Primary factorial: CSR/SSR × TanStack/Next data cache off/on × Redis off/on × client-egress delay 0/40/170 ms; 30 independent seeded repetitions per cell. Configurations are globally shuffled with order seed 20261020. Matching seeds share page sequences. One sequential user at a time.

Every run uses a distinct namespace in both Redis and the Next fetch URL, which resets logical cache state without restarting warmed processes. QueryClient and browser HTTP cache start empty in each new browser context. Two contexts: first follows [A,A+1,A,A+1,A+2,A+1], second requests A once. A is seeded uniform in 1..190; page size is 25 rows. This produces compulsory misses, revisits and one cross-session reuse observation. These synthetic sequences are controlled reuse cases, not estimates of production popularity. TTL and staleTime are one hour; each run must complete within that time. No writes occur.

All modes retain the original router.push search-parameter navigation. A separate action nonce forces route evaluation; it is excluded from data cache keys. Automatic link prefetch is absent. The Next client router may still affect navigation; request counts and response identifiers audit the actual path. CSR query retry, focus and reconnect refetch are disabled. Cache-off uses staleTime=0 and gcTime=0. Cache hits may not be inferred from old response timing headers.

Warm-up: one six-action, two-context sacrificial session per cache/render configuration before each sweep, using pages 195..197 and unique namespaces. All warm-up observations are retained separately. This is a fixed warm-up, not a claim of demonstrated stationarity; cold browser and cold data-cache observations (first context initial action) are reported separately from repeat actions. Process/JIT startup is excluded from primary data; a separate startup sweep records it. Warm-up adequacy is assessed from recorded early/late repetitions, not by deleting outliers.

Linux tc netem on client eth0 delays outgoing traffic only, by 0/40/170 ms, without bandwidth/loss/reordering settings. This is asymmetric emulation, not a complete WAN profile. Eleven TCP connection probes to web and API precede each run; report medians and distributions, never assume the configured delay equals RTT. Docker control traffic does not traverse the shaped interface. Internal web–API is unshaped.

Primary endpoint: elapsed time from navigation time origin (hard load) or the performance mark immediately before router.push (navigation) to a MessageChannel task posted in the first requestAnimationFrame following MutationObserver detection of the first requested data row entering the DOM. DOM time is also retained. This is a DOM/frame proxy, not proof of physical display, FCP, LCP, hydration completion or subjective user experience. Wait for hydration before clicking. Assert requested product ID and nonnegative intervals. SSR rows are detected before hydration. Browser 1280×900, headless Chromium.

API service time includes JSON serialization and synchronous audit logging is performed after the timer stops but before send. Each actual API response has a unique ID; independent API logs record Redis hit/miss/off, DB duration, Redis lookup/set duration and bytes. Front-cache hits are verified by reusing the response ID with no new API record. CSR and SSR are never assumed to have equal conditional Redis hit ratios. Report DB queries/user action and cache payload bytes; do not infer throughput or scalability.

Analysis unit: independent run mean, separately for first initial, cross-session initial and repeat navigation. Use 10,000 seeded percentile bootstrap resamples of run means for 95% confidence intervals. Descriptive paired cache effects may be reported using matched seeds; no significance declarations or multiple uncorrected hypothesis tests. No P99 inference. Preserve failed runs and exclude only protocol violations, explicitly documented. Five numerical spot checks use independent raw-log arithmetic.

Safety: pgrep -f harness.mjs must exit 1 before every measurement batch, monitored at 250 ms and checked afterward. Abort and invalidate an overlapping batch and stop only our own client immediately; fail closed on unavailable process enumeration. caffeinate -i -s -w keeps the Mac awake during each Docker measurement command. Never operate on cachebed containers or any remote host. Own project unibench only, host ports 23000/25001/25432/26379.


## Startup characterization amendment (before its measurements)

A separate companion sweep follows completion of primary measurement. Three independent paired repetitions per eight mode/cache cells, randomized with order seed 20261021, at zero client-egress delay. Restart only own web/API processes before each pair; PostgreSQL and Redis remain running but use unique logical cache keys. TCP-only readiness avoids warming application routes. Run the same six-action session plus fresh-context revisit in a cold-process namespace, then repeat in a new namespace on warmed processes; compare only first-context initial observations between pair members. Both members start with empty browser, Next-data and Redis key namespaces. Preserve all companion observations by separate startup-cold/startup-warm phases. This is limited startup characterization with three pairs/cell, not a precise cold-start distribution or a replacement for 30-repetition primary intervals. No cold-process inference is retrofitted into the primary data.


## Addendum: symmetric-delay sensitivity (separate sweep)

Eight mode and cache cells at 40 and 170 ms added round trip, 30 seeds, order seed 20261023 (480 runs), manifest in `results/raw-symmetric/symmetric-manifest.json`. Each delay is split evenly: half on client egress and half on web and API egress toward the client only (destination-filtered netem band applied from a sidecar sharing each container's network namespace), leaving the internal web-to-API link unshaped. The Docker VM has no ifb device, so ingress shaping inside the client was not available. The primary sweep is unchanged, and the symmetric sweep is analysed and reported separately. One process-guard abort occurred before a run started (a shell process matched the guard); it is retained in `results/raw-symmetric/batches.jsonl` and affected no recorded run.
