# Next.js cache placement and data-visible latency study


Code, frozen protocol, raw measurements, cache-path audits and analysis for a factorial experiment on browser data-visible latency in a Next.js, Express, PostgreSQL and Redis application: CSR/SSR × upper-layer cache × Redis × three client-egress delays, 720 seeded runs and 5,040 browser actions.

The associated manuscript is unpublished. The Zenodo archive DOI is added with the first release.

## Contents

- `results/PROTOCOL.md` — frozen protocol; `results/INCIDENTS.md` — preparation incidents and excluded attempts.
- `results/raw/` — run manifest, per-action browser observations, API audit events, environment record and the independent SQL check (hashes in `results/derived/raw-sha256.json`).
- `results/derived/` — run-level summaries, cache-path audit, action-class summaries and paired contrasts regenerated by `results/analyze`.
- `results/raw-symmetric/` — a separate 480-run symmetric-delay sensitivity sweep (eight cells at 40 and 170 ms with the added round trip split between client egress and the return direction), its manifest and raw logs; analysed by `results/analyze-symmetric.py`. Run with `app/run-symmetric`.
- `app/` — application, benchmark harness and the synthetic dataset.

## Reproduce

Analysis only (no Docker): Python 3.11+.

```sh
python3 -m venv .venv
.venv/bin/pip install -r results/requirements.txt
UNI_PYTHON="$PWD/.venv/bin/python" results/analyze
```

A fresh collection needs macOS, Docker Desktop with NET_ADMIN, Node.js 22 and `./app/run-benchmark`; see `results/README.md`. Delays are emulated with `tc netem` on client egress only, on one host, so results do not generalize to real networks or other frameworks.
